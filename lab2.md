## Код программы

```cpp
#include <iostream>
#include <queue>
#include <chrono>

using namespace std;
using namespace chrono;

// Базовый уровень: Шаблонная функция
template <typename T>
T getOrDefault(T arr[], int n, int index, T defaultValue) {
    return (index >= 0 && index < n) ? arr[index] : defaultValue;
}

// Продвинутый уровень: Шаблонный класс FixedQueue
template <typename T, int N>
class FixedQueue {
    T data[N];
    int head = 0, tail = 0, count = 0;
public:
    bool enqueue(const T& val) { // O(1)
        if (isFull()) return false;
        data[tail] = val;
        tail = (tail + 1) % N;
        count++;
        return true;
    }
    bool dequeue() { // O(1)
        if (isEmpty()) return false;
        head = (head + 1) % N;
        count--;
        return true;
    }
    T front() const { return data[head]; } // O(1)
    bool isEmpty() const { return count == 0; } // O(1)
    bool isFull() const { return count == N; } // O(1)
};

int main() {
    // Демонстрация работы getOrDefault
    int arr[] = {10, 20, 30};
    cout << "getOrDefault(1): " << getOrDefault(arr, 3, 1, -1) << endl;
    cout << "getOrDefault(5): " << getOrDefault(arr, 3, 5, -1) << endl;

    // Демонстрация работы FixedQueue
    FixedQueue<int, 3> q;
    q.enqueue(1); q.enqueue(2); q.enqueue(3); q.enqueue(4); // 4 не добавится
    cout << "Front: " << q.front() << endl;
    q.dequeue();
    cout << "Front after dequeue: " << q.front() << endl;

    // Экспериментальное сравнение (замер вставки/извлечения 1 млн элементов)
    const int TEST_N = 1000000;
    auto start = high_resolution_clock::now();
    queue<int> stl_q;
    for(int i = 0; i < TEST_N; i++) { stl_q.push(i); stl_q.pop(); }
    auto end = high_resolution_clock::now();
    cout << "Time std::queue: " << duration_cast<microseconds>(end - start).count() << " mks" << endl;

    return 0;
}
```

## 1. Что такое О-нотация (Big O) и зачем она нужна?

**Big O** — математическая запись того, как быстро растёт время работы (или память) алгоритма при увеличении размера входных данных `n`. Показывает **верхнюю границу** роста, отбрасывая константы и младшие члены.

**Зачем:** сравнивать алгоритмы независимо от железа, языка и конкретных чисел — важно, как алгоритм масштабируется (O(1) лучше O(n), O(n) лучше O(n²)).

---

## 2. Какая сложность у доступа к элементу массива по индексу? Почему?

**O(1)** — константная.

**Почему:** массив в памяти лежит непрерывным блоком, и адрес элемента вычисляется арифметически: `адрес = начало + индекс * размер_элемента`. Одна операция — не зависит от `n`.

---

## 3. Какая сложность у бинарного поиска? Почему?

**O(log n)**.

**Почему:** на каждом шаге область поиска **делится пополам**. После `k` шагов остаётся `n / 2^k` элементов. Поиск заканчивается, когда `2^k = n`, то есть `k = log₂ n`. Требует **отсортированного** массива.

---

## 4. Что означает сложность O(n log n)? Приведите пример алгоритма.

Время растёт как `n`, умноженное на `log n` — чуть быстрее линейного, но гораздо медленнее квадратичного.

**Примеры:** быстрая сортировка (QuickSort, в среднем), сортировка слиянием (MergeSort), пирамидальная сортировка (HeapSort).

---

## 5. Что такое амортизированный анализ? Приведите пример.

Оценка **средней стоимости операции в худшем случае за серию операций**, а не за одну. Редкая дорогая операция «размазывается» по множеству дешёвых.

**Пример:** `push_back` у `std::vector`. Обычно O(1), но при переполнении буфер перевыделяется за O(n). Амортизированно — **O(1)** на операцию.

---

## 6. Какая сложность у двух вложенных циклов по n итераций каждый?

**O(n²)** — квадратичная.

Внешний цикл `n` раз, внутренний для каждого — тоже `n` раз → `n * n = n²` операций.

---

## 7. Какая сложность у рекурсивного вычисления чисел Фибоначчи?

**O(2ⁿ)** — экспоненциальная (точнее, O(φⁿ), где φ ≈ 1.618 — золотое сечение).

**Почему:** каждый вызов `fib(n)` порождает два вызова `fib(n-1)` и `fib(n-2)`, дерево рекурсии растёт экспоненциально. Мемоизация снижает до O(n).

## 8. Что такое шаблоны функций? Как их объявить и использовать?

Шаблон функции — «заготовка» функции, где тип данных задаётся параметром. Компилятор создаёт конкретную версию под каждый используемый тип.

## 9. Что такое шаблоны классов? Как их объявить и использовать?

Шаблон класса — это «заготовка» класса, параметризованная типами (или значениями), по которой компилятор генерирует конкретные классы.

Объявление: `template <typename T> class MyClass { T data; };`
Использование: `MyClass<int> obj;`

## 10. В чём преимущество шаблонов перед перегрузкой функций?

- Один шаблон покрывает все подходящие типы — не нужно писать N перегрузок.
- Меньше дублирования кода, проще поддержка.
- Работает с пользовательскими типами без изменений.
- Типобезопасность и оптимизация на этапе компиляции (нет накладных расходов).

## 11. Как указать, что шаблонный параметр — тип?

Ключевым словом `typename` (или `class`) перед именем параметра:
`template <typename T>` — T является типом.

## 12. Можно ли создать шаблон с несколькими параметрами типов?

Да. Например: `template <typename T, typename U> class Pair { T a; U b; };`
Использование: `Pair<int, double> p;`

## 13. Как провести экспериментальное измерение времени выполнения?

Использовать `std::chrono::high_resolution_clock`:
```cpp
auto start = std::chrono::high_resolution_clock::now();
// код
auto end = std::chrono::high_resolution_clock::now();
auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();
```
## 14. Почему при измерении времени нужно выполнять операцию многократно?

- Точность таймера ограничена — одна операция может быть короче разрешения таймера.
- Сглаживаются случайные колебания (кэш, планировщик, шумы ОС).
- Получаем статистически устойчивое среднее время.
- Позволяет отличить реальное время работы от единичного выброса.

## 15. Что важнее: сложность алгоритма или константа?

Зависит от размера входных данных:
- При больших N важнее асимптотическая сложность (O-нотация).
- При малых N константа и накладные расходы могут быть решающими.
